# OptiPlot 路线图 / Roadmap

> 面向合作者。说明这个项目**是什么、不是什么、按什么顺序做、以及为什么这样定**。
> 状态：2026-09-20 定稿。中文为主，关键术语保留英文。

---

## 一句话定位

给光学实验数据画图：导入数据 → 看到**能画哪些图**、**为什么能画**、**推荐程度** → 充分调参 → 导出可复现的成品图。

## 明确不做的事

这几条是项目的边界，不接受"顺手加一下"：

- **不做统计分析。** 不判显著性、不做假设检验、不给置信区间。推荐等级是结构适配度，不是统计置信度。
- **不自动加工数据。** 不平滑、不插值、不补断点、不自动归一化、不静默平均重复坐标。
- **不虚构不确定度。** 误差棒只来自显式误差列或真实重复观测；单点组宁可标注"n=1，无法给出误差"也不画误差。
- **不在图里放引用来源。** 每张图下面挂 DOI / 证据级别 / "参考某论文" 已明确移除。产品输出就是图，不是文献综述。
- **不做通用图表库。** 只服务光学场景（光谱、偏振、光束扫描、器件比较、响应度、调制带宽等）。

## 题录与 DOI 的定位

`catalog/papers.json` 保存题录与 DOI，**只用于项目级说明**——证明本项目的图型集合来自对顶刊图表的实际阅读，并可举若干例子（见 `docs/literature.md`）。

`catalog/styles.json` 是图型子类库，**不含任何出处字段**：只有 `id` / `label` / `patterns` / `data_schema` / `recipe`。

它们都**不是**产品运行时依赖：`recommend()` 历史上从未读取过案例库（`catalog_path` 参数声明后未被引用，现已删除），界面也不得在每张候选图下展示证据或来源。

因此对合作者的要求是：新增图型时，题录可以作为**你调研的凭据**保留，但不要把它接进渲染路径或界面。

## 架构分层

```
数据文件  →  core.py 剖析     →  recommend() 规则  →  推荐列表（等级 + 解释）
                                          ↓
                              render.py 确定性渲染  →  PNG / SVG / PDF
                                          ↓
                              export.py 可复现包（数据 + 配方 + 独立脚本 + 校验和）
```

关键不变量：**`render.py` 的分支数决定"能画什么"，案例 JSON 的数量不决定。** 想增加可画的图，必须写渲染分支和推荐规则，加 JSON 记录无效。

| 文件 | 职责 |
|---|---|
| `optiplot/core.py` | 导入、验证、变量角色启发式、推荐条件与等级 |
| `optiplot/render.py` | 确定性 Matplotlib 渲染器，消耗显式编码契约 + 样式参数 |
| `optiplot/export.py` | 可复现 ZIP：完整表格、配方、SHA-256、独立脚本、三种图片 |
| `optiplot/cli.py` | 批量导出 |
| `catalog/styles.json` | 图型子类库：`label` / `patterns` / `data_schema` / `recipe` |
| `catalog/papers.json` | 题录，项目级凭据，不进渲染路径 |

## 核心设计原则（这些是踩坑换来的，不要为了简化而丢掉）

1. **误差棒保守。** 显式误差列优先；否则要求同一横轴取值上有 ≥2 个真实重复观测，分组分别统计。
2. **折线保留采集顺序与缺失间断。** 不排序、不跨缺失连线。
3. **有符号量必须零中心。** 正负混合的数据默认用发散色图并把无色钉在 0。
4. **偏振响应有负值时不画普通极坐标半径**，改用角度–响应折线以保留符号。
5. **二维网格要求坐标唯一且覆盖完整**，重复坐标不静默平均。
6. **角度单位靠猜时必须写进 notes 要求用户确认**，不假装知道。
7. **无穷值转缺失并记录数量**，不静默丢弃。
8. **编号列与常量列不参与相关性或自动坐标选择。**
9. **图内数据配色与界面主题解耦。** 曲线始终用色盲安全的 Okabe-Ito 调色板；换界面皮肤不得改变导出图，否则可复现包失效。
10. **对数轴强制校验全值 > 0**，不静默截断。

## 推荐等级（取代数值评分）

原先每条推荐带一个 48–98 的整数分。**已决定移除**——一位数的精度差异是伪精确，容易被误读成置信度。

改为三档：

| 等级 | 含义 | 判定语义 |
|---|---|---|
| **高** | 数据结构完整满足该图型的全部前提，几乎不会画错 | 前提条件全部成立（如：完整网格 + 第三量为数值） |
| **中** | 能画，但有需要用户确认的假设 | 存在单位猜测、分组归属歧义、样本量偏小等 |
| **低** | 技术上可画，通常不是最佳表达 | 兜底选项（如数据表、宽矩阵相关性） |

同一档内保留一个**不对外显示**的内部排序键 `rank`，用于稳定输出顺序。界面上只呈现等级，不呈现数字。

**判定线在哪里**：等级反映"数据是否满足该图型的前提"，不反映"用户意图是否明显"。区分两种情况：

- 分组箱线图判**高**——它的前提（存在显式分类列、≥2 组、每组≥2 个数值观测）全部可以从数据本身验证。
- 由重复行推算的"均值 ± SD"判**中**——它必须**推断**同一横轴取值上的多行就是重复实验，这个判断数据给不出来，只能由作者确认。

新增规则时用同一条线自检：如果降级理由能被测试断言覆盖，那它其实是前提未满足，应该判低或不推荐；如果理由是一句"请确认"，那才是中。

## 里程碑

### N1 · 数据层纯化 ✅ 已完成（2026-09-20）
- `cases.json` → `catalog/styles.json`，只保留 `label` / `patterns` / `data_schema` / `recipe`（108 → 108 条，无重复无缺失，67.8 KB → 30.0 KB）
- 移除 `evidence` / `visual_review` / `checked_date` / `implementation_scope` / `figure` / `source_url` / `paper_id` 七类逐条出处字段
- `papers.json` 保留，定位改为项目级凭据
- `test_catalog_links_and_counts` 已替换为三个测试：图型引用有效性、出处字段不回潮、题录自身完整性
- 移除 `app.py` 的"论文图表案例"Tab（案例库唯一的运行时读者）与 `recommend()` 的死参数 `catalog_path`
- 新增 `render.FIGURE_TYPES` 作为图型 ID 权威列表
- README 与 `docs/{architecture,literature,validation}.md` 同步
- **判据达成**：47 项测试全绿；渲染路径与界面中不存在证据字段

### N2 · 界面契约冻结
只保留四块：**图 / 参数 / 解释 / 等级**。数据检查与样式预设降级为抽屉。
- **判据**：用户点一遍认可"不冗余"

### N3 · 样式参数系统（**范围最大的一档，优先级高**）
理由：审美因人而异，改一点点观感差别很大；这是当前最大的功能缺口——现在可调的只有 `size / fit / angle_unit / error_type / title / xlabel / ylabel / xlog / ylog / dpi`，字体、线宽、线型、标记、图例、刻度全部不可调。

详细清单见下方"样式参数清单"。
- **判据**：每个参数有对应测试；预览与导出逐像素一致

### N4 · 解释引擎
从 `recipe` + 用户数据的实际结构事实动态生成说明，包含"你可能画错了"这类提示。
例：检测到三个响应列但列名是 `device_A/B/C` → 说明"若这是同一器件的三次测量而非三个器件，应改用误差棒而非三条线"。
- **判据**：每类图型有可验证的解释模板，解释中的每个数字都来自 DataProfile

### N5 · 图型扩充
这才是"扩充可选的图"的唯一有效路径。按光学领域实际频次排序：

| 新图型 | 领域理由 |
|---|---|
| 瀑布图 / 堆叠光谱 | 时间分辨、角度分辨光谱的标准画法，现在只能用多条折线凑 |
| 双 Y 轴 | 透射+反射同图、I–V 与功率同图 |
| dB 刻度极坐标方向图 | 远场辐射/散射方向图；现有 `polar` 是线性半径，画天线类数据是错的 |
| 散点 + 边缘分布 | 器件批次同时看相关与分布 |
| CDF / 累积分布 | 良率、击穿场强统计 |
| Poincaré 球 | 偏振态的标志性表达 |
| 色散 / 能带图 (k–ω) | 光子晶体核心图 |
| 拟合残差子图 | 让现有 OLS 拟合的可信度可见 |
| Mueller 矩阵图 | 比通用矩阵热图更有针对性（标注对称性） |
| Bode 图（幅值 + 相位） | 探测器带宽、调制响应 |
| 小提琴图 / 分组柱状 | 补充箱线与器件比较 |

- **判据**：每个新图型带推荐规则、失效边界测试、至少 3 个 styles.json 子类

### N6 · 图型子类库与关键词检索
`styles.json` 天然就是"大类 → 小类"结构（折线下分实线/虚线/点划、有无边缘填充、同色编码对照实验等）。支持用户输入数据 + 关键词，在子类库内自行选择。
- **判据**：检索命中 `data_schema` / `label` / `recipe`；子类可一键套用样式

### N7 · Web 化替换 Tkinter
FastAPI + 单文件前端（零构建步骤），为 N8 的 three.js 预留同一块视图区域。
放在功能增量之后，因为**换技术栈不产生任何新能力**。
- **判据**：引擎一行不改，45+ 测试仍绿，新增端到端测试

### N8 · 实物光路图 → 3D（第二阶段）
关键设计：让多模态模型输出**结构化场景 JSON**（元件类型、位置、朝向、波长），再由 three.js 确定性渲染。不要让模型直接生成 3D 渲染图——像素不可编辑、几何与比例常错。

```json
{"components":[{"type":"laser","pos":[0,0,0],"dir":[1,0,0]},
               {"type":"bs","pos":[120,0,0],"rot":45},
               {"type":"lens","pos":[240,0,0],"f":80}],
 "wavelength_nm":1550}
```

注意：本项目是**交付给他人本地运行**的软件，Qoder Skill 是开发期指令、不是运行时组件，因此该能力必须实现为真实 Python + 用户自备 API key，无 key 时降级为纯本地模式。

## 样式参数清单（N3 的范围）

**A 排版** — 字体族（含中英混排回退链）、基准字号、标题/轴标签/刻度/图例/注释/colorbar 各自独立字号、字重、标签换行宽度、labelpad 与 tick pad

**B 画布** — 尺寸预设（single 88.9 mm / double 182.9 mm / slide 16:9 / 自定义 mm 或 in）、宽高比锁定、四边留白、constrained/tight 布局开关、背景色

**C 坐标轴** — 四条脊线各自显隐、脊线宽与色、主/次刻度、刻度方向（in/out/both）、刻度长宽、刻度数量与角度、刻度标签小数位/有效位/科学计数法阈值、轴范围自动或手动、对称于零、边距比例、反转轴、对数轴（x/y/both + base + 正值校验）、网格主/次与线型色透明、网格在数据前或后（zorder）

**D 数据系列** — 线型（实/虚/点/点划 + 自定义 dash pattern）、线宽、标记形状（`o s ^ v < > D d p h + x . ,`）、标记大小、填充（实心/空心/半填充）、标记边宽与边色、`markevery` 抽稀、仅连线/仅散点/阶梯线、alpha、zorder、误差棒（capsize、帽宽、方向 y/x/both、颜色是否跟随系列）、`fill_between`（透明度、是否只填差异区）、散点（大小映射列、颜色映射列、边界、rasterize 阈值）、柱（宽度、对齐、分组或堆叠、边缘）、热图（色带、插值、shading、colorbar 位置与厚度与标签与刻度格式、是否叠加数值、对称中心）

**E 图例** — 9 个锚点 + 轴外 + 无、列数、边框、圆角、背景透明度、字号、图例标题与标题字号、条目顺序、手柄长度与缩放

**F 颜色** — 分类调色板（Okabe-Ito 默认 / Tol bright / Tol vibrant / Tol muted / 用户自定义十六进制序列）、单系列颜色覆盖、分组配色映射；用户自定义红绿对时给出色盲警告但不禁止

**G 标注** — 图题、副标题、选中数据点标数值、比例尺/标尺（光学显微与光束图常用）

**H 导出** — 格式（PNG/SVG/PDF/TIFF）、预览与导出 DPI 分离、SVG 字体输出为路径或文本（影响 Illustrator 可编辑性）、PDF 字体嵌入类型、透明背景开关、一次输出多尺寸

**I 样式预设** — 上述全部参数可存为 JSON 配方并复用，让同一课题组保持统一出图风格；配方进入可复现 ZIP

## 给合作者：新增一个图型的正确顺序

1. 定义图型 ID 与**完整的列编码契约**（需要哪些列、什么角色、缺了会怎样）
2. 在 `core.py` 的 `recommend()` 加适用条件与**等级**，并写清"为什么是高等级/为什么只是中"
3. 在 `render.py` 的 `_draw()` 加分支，显式消耗 `Recommendation.encodings`，不读全局状态
4. 用**真实失效边界**验证：空列、全缺失、单点、含负值、含 inf、超宽矩阵、重复坐标
5. 在 `catalog/styles.json` 补至少 3 个子类
6. 不要在渲染路径或界面里引用出处字段

**不要**把参考论文里的复杂功能直接写成已实现的产品功能。

## 环境

`pyproject.toml` 为权威依赖来源；`requirements.txt` 与其保持同步。测试用 `pytest`，CI 在 Python 3.10 / 3.12 / 3.13 上运行。

`.venv` 可能因换机器而失效——`launch.py` 会依次探测项目环境、系统 Python、Conda 环境，只选择依赖完整者，绝不联网安装或修改环境。
