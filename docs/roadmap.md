# OptiPlot 路线图 / Roadmap

> 面向合作者。说明这个项目**是什么、不是什么、按什么顺序做、以及为什么这样定**。
> 状态：2026-09-20 定稿。中文为主，关键术语保留英文。

---

## 一句话定位

给光学实验数据画图：导入数据 → 看到**能画哪些图**、**为什么能画**、**推荐程度** → 充分调参 → 导出可复现的成品图。

## 明确不做的事

这几条是项目的边界，不接受"顺手加一下"：

- **不做统计分析。** 不判显著性、不做假设检验、不给置信区间。推荐等级是结构适配度，不是统计置信度。
- **不自动加工数据。** 不平滑、不插值、不补断点、不自动归一化、不静默平均重复坐标。
- **不虚构不确定度。** 误差棒只来自显式误差列或真实重复观测；单点组宁可标注"n=1，无法给出误差"也不画误差。
- **不在图里放引用来源。** 每张图下面挂 DOI / 证据级别 / "参考某论文" 已明确移除。产品输出就是图，不是文献综述。
- **不做通用图表库。** 只服务光学场景（光谱、偏振、光束扫描、器件比较、响应度、调制带宽等）。

## 题录与 DOI 的定位

`catalog/papers.json` 保存题录与 DOI，**只用于项目级说明**——证明本项目的图型集合来自对顶刊图表的实际阅读，并可举若干例子（见 `docs/literature.md`）。

`catalog/styles.json` 是图型子类库，**不含任何出处字段**：只有 `id` / `label` / `patterns` / `data_schema` / `recipe`。

它们都**不是**产品运行时依赖：`recommend()` 历史上从未读取过案例库（`catalog_path` 参数声明后未被引用，现已删除），界面也不得在每张候选图下展示证据或来源。

**但案例库不是没有用。** 它的作用是**决定接下来写什么代码**——读过的图多了，才会知道还有哪些画法当前这套渲染器不支持。所以扩充文献记录是**设计输入**，值得投入；只是它不会自动变成能力，必须落成 `render.py` 的新分支。**图型库界面**（N2）就是让这套记录变成可浏览、可搜索、能看出哪里是空白区的地方。

因此对合作者的要求是：调研记录照常积累，但把它当作排产依据，而不是往运行时里接。

## 架构分层

```
数据文件  →  core.py 剖析     →  recommend() 规则  →  推荐列表（等级 + 解释）
                                          ↓
                              render.py 确定性渲染  →  PNG / SVG / PDF
                                          ↓
                              export.py 可复现包（数据 + 配方 + 独立脚本 + 校验和）
```

关键不变量：**`render.py` 的分支数决定"能画什么"，案例 JSON 的数量不决定。** 想增加可画的图，必须写渲染分支和推荐规则，加 JSON 记录无效。

| 文件 | 职责 |
|---|---|
| `optiplot/core.py` | 导入、验证、变量角色启发式、推荐条件与等级 |
| `optiplot/render.py` | 确定性 Matplotlib 渲染器，消耗显式编码契约 + 样式参数 |
| `optiplot/export.py` | 可复现 ZIP：完整表格、配方、SHA-256、独立脚本、三种图片 |
| `optiplot/cli.py` | 批量导出 |
| `catalog/styles.json` | 图型子类库：`label` / `patterns` / `data_schema` / `recipe` |
| `catalog/papers.json` | 题录，项目级凭据，不进渲染路径 |

## 核心设计原则（这些是踩坑换来的，不要为了简化而丢掉）

1. **误差棒保守。** 显式误差列优先；否则要求同一横轴取值上有 ≥2 个真实重复观测，分组分别统计。
2. **折线保留采集顺序与缺失间断。** 不排序、不跨缺失连线。
3. **有符号量必须零中心。** 正负混合的数据默认用发散色图并把无色钉在 0。
4. **偏振响应有负值时不画普通极坐标半径**，改用角度–响应折线以保留符号。
5. **二维网格要求坐标唯一且覆盖完整**，重复坐标不静默平均。
6. **角度单位靠猜时必须写进 notes 要求用户确认**，不假装知道。
7. **无穷值转缺失并记录数量**，不静默丢弃。
8. **编号列与常量列不参与相关性或自动坐标选择。**
9. **图内数据配色与界面主题解耦。** 曲线始终用色盲安全的 Okabe-Ito 调色板；换界面皮肤不得改变导出图，否则可复现包失效。
10. **对数轴强制校验全值 > 0**，不静默截断。

## 推荐等级（取代数值评分）

原先每条推荐带一个 48–98 的整数分。**已决定移除**——一位数的精度差异是伪精确，容易被误读成置信度。

改为三档：

| 等级 | 含义 | 判定语义 |
|---|---|---|
| **高** | 数据结构完整满足该图型的全部前提，几乎不会画错 | 前提条件全部成立（如：完整网格 + 第三量为数值） |
| **中** | 能画，但有需要用户确认的假设 | 存在单位猜测、分组归属歧义、样本量偏小等 |
| **低** | 技术上可画，通常不是最佳表达 | 兜底选项（如数据表、宽矩阵相关性） |

同一档内保留一个**不对外显示**的内部排序键 `rank`，用于稳定输出顺序。界面上只呈现等级，不呈现数字。

**判定线在哪里**：等级反映"数据是否满足该图型的前提"，不反映"用户意图是否明显"。区分两种情况：

- 分组箱线图判**高**——它的前提（存在显式分类列、≥2 组、每组≥2 个数值观测）全部可以从数据本身验证。
- 由重复行推算的"均值 ± SD"判**中**——它必须**推断**同一横轴取值上的多行就是重复实验，这个判断数据给不出来，只能由作者确认。

新增规则时用同一条线自检：如果降级理由能被测试断言覆盖，那它其实是前提未满足，应该判低或不推荐；如果理由是一句"请确认"，那才是中。

### N3a · 图型无关参数系统 ✅ 已完成（2026-09-21）
理由：审美因人而异，改一点点观感差别很大；且这是当前最大的功能缺口——原先可调的只有 `size / fit / angle_unit / error_type / title / xlabel / ylabel / xlog / ylog / dpi`，字体、线宽、线型、标记、图例、刻度全部不可调。

**已完成**：`optiplot/style.py` 参数管道（六个应用点：rcParams / Figure 构造 / 逐 artist 字体 / savefig / 逐 Axes 配置 / 逐次 legend 调用 + 未知键报错）；A 排版组；B 画布的 `size`；C 坐标轴组（脊线显隐与线宽色、刻度方向与长短宽、次刻度、刻度旋转与数量上限、小数位、科学计数阈值、offset 开关、轴边距、手动范围、反转、对称于零、网格主次与线型色透明与压层）；E 图例组；F 颜色组。新增 84 项测试。

**过程中删掉的一个功能**：原计划"用户自定义红绿配色时给出色盲警告"。实现后校准发现它站不住——四套内置色盲安全调色板内部的最小两两距离是 **0.17–0.24**，而被判为"混淆"的红绿对距离是 **0.37–0.48**，比合法配对还大。这个 RGB 启发式区分不了"混淆"与"正常"，阈值定在哪儿都是假装有依据，**已删除**。保护来自只提供经过验证的调色板，不来自一个自称能评判你自定义配色的分数。要做对需要感知色空间（CIELAB/CAM16）加真实 CVD 模型，另立事项。

**两条 Matplotlib 事实**（都已有测试钉住）：`legend.ncols` **不是** rcParam，列数只能逐次传给 `ax.legend()`，因此有独立的 `legend_kwargs()` 应用点，且 `Legend` 只有 `set_ncols` 没有 getter，列数的可观察证据落在像素摘要测试里；`legend.loc` 是**带校验的** rcParam，`"auto"` 不被接受（它只是 `ax.legend(loc=)` 的合法实参），Matplotlib 自己的自动放置叫 `"best"`，`"none"` 由 `_legend()` 拦截、不进 rcParams。

**F 组的一条边界**：`custom_colors` 只在 `palette="custom"` 时生效，否则直接报错——不报错的话用户会输六个十六进制然后什么都没发生。颜色格式强制 `#RRGGBB` 七位，`#123` 简写与裸 `123456` 都拒绝。

**C 组的一条设计约束**：轴样式只作用于 `AXIS_STYLED` 里的图型（折线、散点、分箱、误差棒、直方图、箱线）。热图/等高线/矩阵/相关/表格/流程图/极坐标**不套用**——pcolormesh 上画网格是噪音，而裁剪热图的轴范围会在"只是调个外观"的外观下藏掉实测样本。脊线与刻度方向对图像类仍然有效（四面框的光束图很常见，也无害）。

**留给 N4 的一条判断**：`y_zero_centered` 用在全为正的数据上是破坏性的——0.3–3.2 mA 会被拉成 ±3.2，纵向分辨率白扔一半。程序不替用户否决（那是"不替用户决定物理表达"的立场），但解释引擎应当说出"这个选择会浪费半张图"。

审计原状：`render.py` 里 13 处 `opts.get` 各写各的约定，约 20 处硬编码样式值（`lw=1.65`、`s=16`、`alpha=0.65`、`ms=4`、`capsize=3`、`gridsize=45`、`levels=14`、`fontsize="small"`、`frameon=False`…）。**先立管道，后续每个新图型对着管道写**，否则新分支会继续累积 ad-hoc 读取和硬编码，最后要回头统一改。

**B 画布（最后完成的部分）**：毫米直接指定尺寸（作者指南用的就是这个单位，优先级高于命名预设）、只给一边时按预设或 `aspect_lock` 推另一边、`layout` 三态（constrained / tight / none）、四边留白、画布与坐标轴背景色。

两条冲突是**报错而不是静默忽略**：自定义留白要求 `layout="none"`（constrained 与 tight 会自行计算子图位置并丢弃 `margin_*`）；`tight_bbox` 与自定义留白互斥（紧裁会抹掉留白）。`aspect_lock` 与同时给定的宽高互斥。

至此 N3a 的 A/B/C/D/E/F/H/I 八组全部落地，`Style` 共 97 个字段（第三批随 `stacked_curves` 增至 99）。下一档是 N4 解释引擎与 N5 图型扩充。

### N3a 补充 · H 导出 与 I 样式预设（已完成）
**H**：导出 dpi 与预览 dpi 分离（屏幕重绘不必按 600 dpi 付费）、SVG 文字输出为可编辑文本或轮廓路径、PDF 字体嵌入类型 42/3、透明背景、紧裁边距与 `pad_inches`。

**I**：`STYLE_PRESETS` 四个跨组预设（`default` / `journal` / `slide` / `poster`），每个改动 10–11 个字段、横跨 A/B/C/D/E/F/H 多组——**一个预设只动一组的话它就不配叫预设**，那只是 `size` 换了个名字。`from_preset(name, **overrides)` 支持在预设上叠加；`save_preset` / `load_preset` 读写纯 JSON，让课题组能共享一份统一出图风格。未知预设名报错并给出最接近的建议，不静默退回 default。

可复现包升到 `format_version: 2`：recipe 里记录**完整解析后的样式字典**（不只是调用方传进去的那几项），并单独附带 `style.json` 与 `style.py`。理由是重放不能依赖"当前版本恰好用什么默认值"——默认值会变，包里的不会。`style.json` 同时就是可复用的预设文件，导出即分享。

`dpi` 从数据选项移入样式（它从来都是呈现问题）。

### N3a 补充 · D 数据系列（已完成）
线宽、线型是否循环、标记形状（21 个码）、标记大小、填充样式（full/none/left/right/top/bottom）、标记边宽、`markevery` 抽稀、阶梯线、仅连线/仅点、系列 alpha、系列 zorder、误差棒帽宽与线宽、散点大小/透明度/描边/rasterize 阈值、等高线层数、六边形分箱密度、pcolormesh shading、色标厚度与间距、差异区填充、堆叠曲线的偏移倍数与填带（`stack_offset` / `stack_fill`，随 `stacked_curves` 落地）。

**这一组抓到的三类"能选不能用"错误**，都已变成测试：
- `image_shading` 的候选里原本有 `"antialiased"`——它不是 pcolormesh 的合法值，matplotlib 只警告然后**静默换成 `auto`**。合法集是 `['gouraud','nearest','flat','auto']`。
- `"flat"` 虽然是合法值，但要求坐标数组每个维度比数据大 1，实测网格永远不满足，直接报错。**能选 ≠ 能用**，已从候选中移除。
- `marker_fill="left"` 原本被当作 `markerfacecolor` 传入，而半填充是 `fillstyle` 参数不是颜色，绘制时抛 `Invalid RGBA argument`。这个 bug 只在**真正绘制**时才暴露——构造图并读属性是查不出来的，所以守卫测试现在强制 `canvas.draw()`。

由此立了一条通用做法：**任何"候选值列表"都要有测试把每个候选走一遍完整绘制**，而不是只断言它能被赋值。见 `test_every_offered_marker_and_fillstyle_survives_a_real_draw` 与 `test_every_offered_choice_is_actually_accepted_by_matplotlib`。

另外删掉了 `error_direction` 字段：它被定义、被校验，但**从未接进渲染器**——是个彻底的死旋钮。而 x 方向误差需要的是 x 误差列，属于数据契约问题，不该放在样式层。
- **判据**：每个参数有对应测试；预览与导出逐像素一致

### N3b · 图型专属参数（**跟随每个新图型**）
瀑布图的堆叠偏移与视角、dB 极坐标的径向刻度类型、Bode 图的双面板耦合、Poincaré 球的网格密度——这些只有写了渲染器才知道要什么。**不提前设计**，避免为还不存在的图型猜参数。

### N4 · 解释引擎
从 `recipe` + 用户数据的实际结构事实动态生成说明，包含"你可能画错了"这类提示。
例：检测到三个响应列但列名是 `device_A/B/C` → 说明"若这是同一器件的三次测量而非三个器件，应改用误差棒而非三条线"。
- **判据**：每类图型有可验证的解释模板，解释中的每个数字都来自 DataProfile

### N5 · 图型扩充（进行中 · 已完成 A 组前五批）
**第一批 13 → 17 类**：两列差值、两列比值、多列极差包络、波长轴 + 光子能量副轴。`sample_spectrum` 的候选数从 4 涨到 8。

**第二批 17 → 20 类**：导数谱、双 Y 轴响应、峰位与半高宽随扫描参量演化。为此新增两份合成样例（`sample_liv_sweep`：电流×电压×光功率；`sample_angle_resolved`：角度×波长×反射率，故意留 14 个缺口），否则新图型违反"注册的图型必须能被推荐到"这条守卫。

**新增时踩到并修掉的一个判断错误**：差值与比值最初只检查"同一网格 + 有效行数够"，于是对光束扫描数据推荐了 **"y_um 减 intensity_au"**——位置减强度，算术成立但物理为空。加了 `_comparable()`：两列必须是同类量（单位相同，或无单位且共享词干），且都不是自变量。

修这个约束时又踩第二个坑：`_unit_of` 最初按"尾部短 token"识别单位，于是把 `device_A` 的 `A` 当成单位，导致 `device_A` 与 `device_B` 被判为不同量——**新图型在最该起作用的数据上消失了**。改成只认真实单位表，并且**不接受单字母尾缀**（`A` 既是安培也是系列标签，歧义代价不对称）。

第二批把这条规则**收窄而不是推翻**：`forward_voltage_V` 的 V 确实是伏特，一刀切拒绝单字母让双 Y 轴在 LIV 数据上根本不出现。现在的判据是"单字母尾缀只有当词干说出该字母所量的物理量时才算单位"——`voltage_V`、`current_A`、`power_W` 算，`device_A`、`channel_B` 不算。歧义没有消失，只是换成了一个能同时保住两侧的规则，并由 `test_trailing_letters_are_units_only_when_the_name_says_so` 钉住。同一批里 `_distinct_quantity` 一度沿用 `_comparable` 的 `_axis_rank` 守卫，把 rank-3 的 voltage/current/power 全排除掉，双 Y 轴于是又在 LIV 上消失；改成只排除裸坐标词干（`x`/`y`），光束图仍不会拿到假的双轴。

**峰位提取的两个数值错误**（`_peak_and_fwhm`）：
- 返回值搞混了幅度与位置——把极值处的**函数值**当成峰位返回，于是"峰位随角度演化"画出来是 1.0/0.5 这种平台值。现在返回抛物线插值后的**横坐标**。
- 候选极值只按"先找极大再找极小"排序，于是一条只有凹陷的平坦反射率曲线里，最大的**噪声尖峰**被当成共振（噪声也能在内部造出一个高于两端点样本的点）。改成取**偏离基线更深**的那个转折点。这条由 `test_a_dip_is_not_confused_with_the_noise_floor_of_a_flat_curve` 钉住。
- 亚像素定位不是装饰：样例里峰每 5° 只移动 8 nm，而网格步长 12.5 nm，取最近采样点会让演化曲线走成台阶，看起来像"没动"。

两条约束都由测试钉住：`test_incomparable_columns_get_no_difference_or_ratio`、`test_series_labels_are_not_mistaken_for_units`。

**新增两条覆盖性守卫**：
- `test_styles_cover_figure_types_except_documented_gaps`：每个图型要么有画法记录，要么出现在 `SPARSE_BY_DESIGN` 里并附理由。留白必须是**写下来的决定**，不能是没人知道的遗漏。名单里的项一旦有了画法，测试会反向报错要求移除。
- `test_every_figure_type_is_offered_somewhere`：注册了却永远不会被推荐的渲染器是死代码不是能力（`matrix_heatmap` 逼这条测试把 NPY 也纳入扫描，因为它只从无坐标数组产生）。

**组织原则是宽度，不是文献频次。** 本项目当前处于吸收阶段——目标是"给定一份数据，能得到多少个都说得通的选项"，而不是"我们已有的图型在文献里出现多少次"。用频次当筛子会恰好砍掉可选性；等实现面铺开后，再按频次做分类和排序是很容易的事。

完整候选清单见 **[figure-inventory](figure-inventory.md)**（约 90 条，按输入数据形状分簇：A 一维扫描 / B 二维网格 / C 散点云 / D 分类分组 / E 角度偏振 / F 频域时域 / G 矩阵张量 / H 分布统计 / I 结构几何 / J 跨切能力）。

**实现按数据形状簇整体推进，不按单条推进**——同簇共用列编码契约、失效边界测试和色标逻辑，一次做完一簇比在簇间来回跳省得多。

**第三批 20 → 21 类：参数分辨曲线族。** `sample_angle_resolved` 原本拿不到"每个角度一条反射率曲线"——分组只认分类列，而仪器导出的角度/温度/延迟步长都是数值列，于是 15 条光谱被连成一条锯齿线（`line_unique` 正确地拒绝了它）。加了 `_parameter_group()`：取**与横轴配对唯一**的第二扫描轴当分组列，2–24 级、每级至少 4 行。唯一性检查是这条规则的全部要点——"15 个角度各一条谱"和"同一点测 15 次"在列结构上的差别就是 (x, 候选) 是否重复，而后者需要的是误差棒，不是一族线。

顺带修正三处：
- 完整网格此前一律拒绝画折线（沿光栅顺序连线会锯齿）。但一旦第二扫描轴把行分成族，每条曲线就是自己那条有序扫描，`grid_like` 不再是否决条件——`(not grid_like or group)`。
- 极坐标不能用自身角度当分组列（每组只剩一个点，是散点不是比较）。
- 分组超过调色板容量（okabe 只有 6 色）时改用连续色带按序取色。15 条曲线里让两条共用一个蓝，比渐变色更难读——它会被读成"同一条"或"重复测量"。

新增 `stacked_curves`（堆叠曲线族，二维瀑布）：同一列契约，把每条曲线按 `stack_offset` × 共享量程逐条上移，`stack_fill` 控制填带。**偏移量取所有曲线的共享量程**而不是各自的，否则"更高的峰"可能只是"更平的那条"。这是 N3b 第一次真正落地：新图型带来两个自己的参数，而不是先猜参数再画图。

**同时补上一个静默缺口**：`AXIS_STYLED` 名单停在 6 个图型，第二批新增的 7 个折线类根本不在册，于是 `grid` / `tick_max` / 轴范围 / 反转对这些图型**静默失效**——测试全绿，因为样式测试的样例走的是 spectrum_lines。现在折线类全部在册，并由 `test_every_figure_type_is_styled_or_declared_exempt` 钉住"在册或显式豁免"二选一；孪生轴继承刻度与范围但 `grid=False`，否则两条轴各画一层横线。

**第四批 21 → 22 类：曲线与峰位标注。** `_peak_and_fwhm` 已经会算峰位与半高宽，但只服务于峰位演化；把它接到单条曲线上就是光学图最常见的"标出 λ_peak 与 FWHM"。`_peak_and_fwhm` 的返回值从三元组改成 `Peak` 命名元组，带上 `value / level / left / right`——**半高宽的两个交点必须跟着数字走**，否则调用方只能自己再找一遍（或者画不出那条跨度线，只能印一个数）。

两条边界由图型本身守住：
- 只在**没有分组、不是完整网格**的数据上推荐。一旦有第二扫描轴，逐条曲线的峰就是 `peak_evolution` 的活，在这里标注等于在十五条谱的锯齿上插一个标记。
- 扫描范围内没有内部极值的曲线**不标注**，并在标题写明"几条未标注"。把单调上升到端点的那一点报成共振，是把仪器范围报成物理。
- 标注文字带半透明底色：三条峰互相交叠的谱里，纯文字压在线上就没法读。

**第五批：把 A′ 的形状真正接住。** 两条：
- **不完整网格的热图**。`_find_grid` 要求 `len(valid) == nx*ny`，于是 14 个丢点就让整张角度×波长图**没有任何面状表达**。新增 `_partial_grid()`：坐标唯一、两轴各 ≥3、覆盖率 60–99% 时以 **medium** 推荐热图并在理由里报出缺测数；渲染器本来就用 `pivot` + `masked_invalid`，空格子中出来就是白。**等值线不在不完整网格上推荐**——contourf 会跨缺测区插值，把没测的地方画成测过的。
- **极坐标的前提补上**。`polar` 原先只看"列名含角度 + 半径非负"，于是角度×波长×反射率的数据拿到一张把 615 个点绕成圈的"响应曲线"，等级还是高。现在要求**每个角度只有一个半径**；有重复时必须找到能把它们分开的列（分类标签或第二扫描轴），且分组后每组仍是一圈有序点，组数 ≤8。找不到就**不推荐**，改由曲线族/热图表达。

这条同时说明 8 条候选上限的一个副作用：新图型挤掉旧图型时，测试里"每个注册图型都必须在某个样例上被推荐到"会立刻变红——第五批就是这样把 `peak_evolution` 挤出前 8 的。**守卫发现的是真问题**（极坐标那条本来就不该占一个高位名额），不是测试太严。

**B 组第一批 22 → 24 类：面状视图。** 先把 `heatmap`/`contour`/`matrix_heatmap` 的网格准备、色带选择、缺测涂色抽成 `_grid_of` / `_surface_colormap` / `_paint_surface`，再往上加图型——否则每个新面状图型都要重写一遍"重复坐标拒绝而不是平均"这条不变量。新增 `heatmap_contours`（颜色保留实测格点、等值线只标等值面位置）与 `heatmap_marginals`（上、右两条沿另一轴的均值剖面）。

三个判断：
- **边缘剖面只做两条不做四条。** 清单原文写"上下左右四条"，但上边与下边是同一条曲线的重复，左边与右边同理。四条只会多占三倍画布说同一句话。已把这条改回清单并注明理由。
- **色标必须占独立一列。** `fig.colorbar(m, ax=ax)` 只收缩主图那一侧，与主图共享 y 的右侧剖面不会跟着收缩，两者就错位了。`heatmap_marginals` 用 2×3 gridspec，色标自占 `grid[:, 2]`。
- **等值线默认色按色带极性自动选。** 顺序色带（viridis）大部分面积是暗的，深色线恰好在值最低、最需要读的外圈消失；发散热色带中部偏亮，反过来要深色。规则是"跨零用深色，否则用浅色"，`contour_line_color` 可覆盖。

新增四个参数：`contour_labels`、`contour_line_color`、`missing_fill`（缺测格涂一个不可能属于色带的颜色，而不是留白——留白在有些色带上与最低值同色）、`marginal_height`。`missing_fill` 用 `cmap.with_extremes(bad=...)`，`set_bad` 已被 Matplotlib 标记待弃用。

剖面数值由测试钉住：上面板必须等于 `z.mean(axis=0)`、右面板等于 `z.mean(axis=1)`，且共享轴在色标占列之后仍然对齐。**两个覆盖性守卫在这批新图型落地时立刻变红**（`AXES_LEFT_ALONE` 与画法记录名单都没跟上），这正是它们被写出来的目的。

**B 组第二批 24 → 25 类：颜色不再直接表示实测值的两种读法。** `heatmap_normalized`（逐行/列 z-score）加上 `mask_below` 阈值屏蔽。三个设计点：

- **归一化口径按"固定哪个坐标"命名**（`per_y` / `per_x`），不叫 row/column——数组轴和图上的行列在转置存储时会反过来，叫错一次就整张图读反。色标标签写明"每个 X 处沿 Y 的 z-score"，因为**跨行同色不代表同值**，这是归一化热图唯一容易被误读的地方。标准差为零的行返回 NaN 留空，不假报 0。
- **屏蔽格与缺测格必须两种颜色。** 前者说"测了，但很小"，后者说"没有数"，意思相反；共用一个灰色就是让读者在两者之间猜。实现上是在主 `pcolormesh` 之上再叠一层只含被屏蔽格的 `ListedColormap` 平面层，缺测格仍走色带自身的 bad 色。数量与阈值写在色标标签第二行。
- **阈值判的是实测值，不是归一化后的值。** 用户设 0.05 意思是测量量的 5%，不是某行标准差的 5%。所以 `_threshold_mask` 在归一化之前算。这条由测试钉住。

`masked_fill` 的可选值**不含 "none"**：留空正是缺测格的样子，允许它等于没有这个开关。

**E 组第一批 25 → 27 类：dB 方向图与多圈扫描。** 三个判断：

- **径向深度跟着数据走，`db_floor` 只做上限。** 固定 −30 dB 会把只有 5 dB 调制的方向图压成外圈一条线，白白扔掉整个半径。现在按 5 dB 向外取整覆盖数据，再由 db_floor 封顶；被封顶截掉的点数写进标题。取整方向曾经写反（向内生成了 −5 dB 底，把 32 个点裁掉），测试钉住了"浅调制不应出现未画点"。
- **10·log10 还是 20·log10 不能从列名猜。** 功率量与场幅量差一个因子 2，选错是标度错误而不是美观问题。默认按功率，并把"按 10·log10"连同 0 dB 参考值一起印在图上——让假设可见，而不是替用户决定。
- **多圈扫描不该单独用极坐标。** 跨度超过一圈时不同圈落在同一条射线上，"这个点属于哪一圈"在图上无法回答。所以检测到 span > 360° 就改推「极坐标 + 直角双显示」，直角面板保留展开顺序。新增 `sample_multi_turn` 样例：四瓣图案叠加两圈之间 18% 的真实衰减，极坐标看不出、直角面板清楚。

直角面板直接画原始度数，不画 `rad2deg(deg2rad(x))` 的往返值——共享轴上的浮点噪声会让两张图讲的不是同一批数。

顺带修掉一个通用冲突：渲染器写在标题位置的是**读图必需的注记**（dB 参考、截断计数、缺峰统计），用户标题现在叠在它上面而不是替换它。

**E 组第二批 27 → 29 类：Mueller 矩阵与 Poincaré 球。** 这一批的关键不是画出来，而是**允许数据自己声明它是什么**：

- `_mueller_columns()` 要求 16 个列名恰好是 `m00…m33` 才认定；`_stokes_columns()` 要求 `S0…S3`。**一个 4×4 的数字块不是矩阵的证据**——绝大多数四行四列的表只是表，凭形状推荐 Mueller 矩阵就是替读者做断言。列名归一化时容忍 `_`、空格、`.` 与大小写（仪器导出常见），但 `signal/s1/s2/s3` 不会被误认成 Stokes。
- **Mueller 色标必须以零为中心且对称于 max|m|。** 元素有正负且符号有物理含义，顺序色带会把负元素读成「数值小」。
- **互易性只报偏差不下结论。** 图上给出 M 与其转置的最大偏差落在哪一对元素；这是否违反互易取决于样品有无磁光/手性组分，是用户的判断，不是引擎的。
- **Poincaré 球不把点投影到球面。** 半径就是偏振度，压到球面等于宣称完全偏振——正是测量要回答的那个量。`|S|/S0 > 1` 的点（噪声、定标漂移、串扰）按实测量画出并在标题计数，不做归一化修正，否则掩盖定标问题。
- 我一开始把"球外"判据写成 `|u|+|v|+|w| > 1`（L1 范数），于是把 (0.6, 0.6, 0) 这类合法偏振态报成不自洽，样例里 13 个点被误判。物理约束在半径上，测试现在直接钉住这一点。
- 球框用三条大圆而不是填充曲面：填充面在多数视角下变成一团，把身后的轨迹挡住。视角 `view_elevation` / `view_azimuth` 做成参数——三维轨迹正对某条轴时会退化成圆盘、轨迹重叠，定稿必须换角度复核。

**Mueller 规则差点被"只有一行 → 表格"的早退吞掉**：一行 16 列是 Mueller 矩阵最常见的导出形状，所以该规则移到早退之前。同时修掉一个通用冲突：渲染器写在标题位置的是读图必需的注记，用户标题现在叠在上面而不是替换它。

`Mᵀ` 用的是 U+02EA，微软雅黑没有这个字形，会画成豆腐块——改成"转置矩阵"。字体无关性由 `-W error::UserWarning` 的渲染跑法守住。

**Jones 矩阵暂缓**：复数输入还没有列约定（实部虚部两列？幅相两列？），猜一个就会让 8 个数被误读成 4 个。等列约定想清楚再做。

**A 组第五批 29 → 30 类：断轴光谱曲线。** 断轴天生是误导性的——它让不连续的坐标看起来连续。所以触发条件不来自用户的审美而来自**数据本身**：`_widest_x_gap()` 要求最大空隔 ≥ 采样中位间隔的 8 倍，且断口两侧各 ≥3 个有效点。稀疏但连续的扫描拿不到断轴（有测试钉住），因为那种情况下连续线本身就是诚实的表达。

三条不可选的必需项：
- **断口标记 + 省略区间必须画出来。** 抹掉它们，读者会把两条独立坐标当一条连续轴读，进而在断口两侧编出不存在的趋势。所以这是图型定义的一部分，不是 `Style` 参数——不提供"关掉断口标记"的开关。
- **两面板 `sharey`。** 峰高跨断口仍然可比；横向斜率不可比，理由里写明。
- **断口两侧不许连线。** 测试直接检查"没有任何被画的点落在省略区间内"。

**一个静默错误被抓出来两次**：先是在 `sharey` 下用 `companion_ax.set_yticklabels([])` 隐藏右面板刻度，结果**两个面板都没有数字**了（它改的是共享的 formatter）——改成逐轴的 `tick_params(labelleft=False)`。接着把 `broken_spectrum` 加进 `AXIS_STYLED` 之后，用户设的 `x_min/x_max` 被套到两个面板上，右面板显示一段**没有数据的区间**却仍标着另一段的名义。现在手动横轴范围与断轴互斥并给出理由（纵轴范围仍然允许，因为两面板本就共用）。

新增 `sample_split_band`：可见光 Si 探测器 400–700 nm 与近红外 InGaAs 1200–1500 nm 拼成的宽谱，中间 500 nm 空洞是量程切换造成的物理不可能，正是断轴唯一正当的用途。

**B 组第一批 30 → 32 类：三维表面与「表面 + 俯视」配对。** 这一批的收获主要不是画法，而是三条 matplotlib 陷阱和一次自我删除：

- **`SURFACE_KINDS` 改名 `PAINTED_GRID_KINDS`。** 原来的名字按字面把 `surface_3d` 卷进了 `pcolormesh` 分支，`QuadMesh` 塞进 `Axes3D` 当场崩掉。元组按**画法**而不是按名字划分，改名是为了让下一个带 "surface" 的三维图型不能被这个单词顺手扫进去。
- **色标必须独占一列。** 3D 面板的色带默认落在盒子右后边缘，那正是 `set_zlabel` 的位置，两处同名量纲叠成一行糊字。所以 `surface_3d` 是 1×2、`surface_with_contour` 是 1×3，最后一列只放色标；只有确认没有独立色标轴时才写 z 标签。
- **`z_exaggeration` 拉的是盒形不是数值。** `ax.set_box_aspect((1, 1, z_exaggeration))`，刻度仍是实测量；z 的量纲和 x/y 不同，本来就不存在"真"比例，用 span 比值只会把单位选择偷偷画进图里。不等于 1 时标题自动带上「纵向拉伸 ×N（此角度下斜率与倾角不可读）」。
- **`surface_shade` 实现之后测出是死的，于是删掉。** matplotlib 3.11 的 `plot_surface(shade=…)` 只在纯色 `color=` 下起作用，一旦给 `cmap=` 就失效——而我们的表面必然带色带。留着一个拨了没反应的参数比没有这个参数更糟，`test_no_surface_shading_knob_exists` 把"它不存在"钉成断言。
- 两个图型都定在 **medium**：透视高度无法对着刻度读、近处挡住远处，理由里直接写"要取数值请改用热图或等高线"。触发条件 `min(dims) >= 5`，5×5 以下的网格立起来只有尖角没有形状。
- 副作用：**8 条候选的上限第一次真正咬人**。取一份 9×7 的完整网格（列名与 `sample_beam_map` 相同）试了一遍，八个位置被 `heatmap`、`contour` 三种热图变体，加上 `spectrum_lines` / `stacked_curves` / `box` 占满，两个三维图型一条都进不去；同一套规则在 41×33 的 `sample_beam_map` 上给得出。也就是说上限不是理论问题，但也还没到要改的程度——先记下机制，免得下次把它当成渲染 bug 查。

**A 组第六批 32 → 35 类：把坐标尺度当成图型，而不是当成美化开关。** 双对数、半对数、累积响应三条。GUI 里本来就有 X log / Y log 两个勾选框，所以这一批要回答的问题不是"能不能画"，而是**推荐引擎什么时候有资格说"这张图在检验某个函数族"**：

- 门槛来自数据而不是偏好：`_decade_span()` 要求横轴跨 ≥2 个数量级、纵轴 ≥1 个，且**全列为正**。有非正值时返回 0.0（"不能取对数"），不是返回一个小跨度——一个零读数就把整列从对数图上取掉，而不是把那个点悄悄删掉。累积图不受此限，积分容得下零。
- 图型自己锁定尺度：`FORCED_LOG` 让 `semi_log` 无论选项怎么写都只把纵轴取对数。勾选框能关掉的东西不该同时是一个图型名。
- **目视斜率是画布的属性，不是数据的属性**：双对数上同一条直线在更方的框里就更陡，所以 `log_aspect_equal` 打开前，图上写的是"目视斜率取决于画布长宽比"；打开后写"45° 即幂指数 1"。等比是用 `set_box_aspect` 之外的 `set_aspect(adjustable="box")` 实现的，代价是留白——实测每十倍频程的像素比从 1.672 变成 1.000。
- **拟合曲线要按它被画出来的那条轴采样**：`_fit_overlay` 原来固定 `linspace(300)`，在双对数上 300 个点全挤进最高那个十倍频程，低波段变成折弦。改成 `geomspace`；参数仍然在线性空间拟合，所以残差条上另写一句"残差在原始数值空间计算，大值点主导"。样例图里这句不是装饰——单指数拟合被前几个点拉着，尾部模型高于数据，残差条把这件事画了出来。
- 累积图三条自律：起点 0 是定义不是测量；只走相邻实测点之间的梯形，跨缺测的**段数**写在图上（连续两个缺测点算一段，不是两段）；末值只覆盖已扫区间，不能被读成全量程总量。`fraction` 模式按曲线自身的最大偏离归一，不按末值，否则有正负抵消的列会除爆。
- 样例：`sample_broadband_det`（250 nm–25 µm 探测器响应，量子极限下幂指数恰为 1，中间留一个大气窗）和 `sample_pl_decay`（3.8 个数量级的衰减加常数背景）。前者拟合回 k=0.9788，后者回 τ=8.868（真值 9.0）。

**顺手抓到一个早就存在的死控件**：`FITTABLE` 里列着 `spectrum_lines`，GUI 因此把"线性拟合"放进下拉，但画线主体只处理具名模型，选 `linear` 什么也不画、也不报错。现在 `_linear_overlay` 让曲线类真的能画 OLS（并沿用单面板惯例，不开残差条），同时 `render()` 在门口就拒绝不可拟合图型收到 `fit`——和删掉 `surface_shade` 是同一条理由：**接受了参数却什么都不改，比没有这个参数更糟**。累积曲线单独给了原因（拟合讲的是原始量的形状，累积曲线讲的是积分之后的量）。

建议批次（2026-09-24 更新，原顺序里断轴、双对数、J 组模型库、E 组偏振、B 组三维都已落地）：A′ 组差分序列（逐条减参考，泵浦-探测的 ΔT/T）与曲线归一化重标 → C/D/H 统计表达（成对图、散点加边缘直方图、柱状加误差棒、Bland-Altman）→ B 组等值面/切片（要先定义体积数据的列契约，现在是四维 (x,y,z,v)，导入层还没有这条路）→ I 组结构示意。8 条候选的上限已经两次实测咬到（完整网格、双对数样例），下一批若再加图型就要先处理它。

**有意留白的图型**：`box`、`density`、`matrix_heatmap`、`distribution` 目前没有画法记录。理由是文献挖掘显示前两种在本地 239 篇图注中几乎不被提及，后两种是数组与单列场景的兜底；它们仍是合法可画的选项，只是不占用吸收阶段的写法预算。这一判断由 `SPARSE_BY_DESIGN` 名单在测试里显式记录，不是无人知晓的遗漏。

文献词汇在此的作用限于**发现候选**（`research/enumerate_plot_vocabulary.py` 从 1625 条图注枚举出 52 种"图的形式"说法，含 `eye diagram`、`constellation`、`bode`、`polar plot`、`stacked`、`inset`），不用于给候选排序。

- **判据**：每个新图型带推荐规则、失效边界测试、至少 3 条画法记录，且能被某个样例数据推荐出来；同一数据形状簇一次做完

### N5b · 物理模型拟合库（已完成第一版）
文献图注里反复出现 "the solid line is a fit to a single exponential function" 这类表述，而此前引擎只有用户勾选的线性 OLS。**这不改变"不自动拟合"的立场**——模型仍必须用户显式选择，但选择面已经打开。

`optiplot/models.py` 七个模型：单指数 / 双指数衰减、幂律、高斯与洛伦兹线型、单振子 Drude-Lorentz 色散、Malus 定律。入口三处共用同一份清单（`FIT_CHOICES`）：GUI 下拉、CLI `--fit`、`options["fit"]`；拼错的模型名**报错而不是退回不拟合**，否则用户以为勾了。

**硬约束已落地**：勾选具名模型后 `render()` 强制生成 `[3.2 : 1]` 的双面板，上图下残差，横轴共享且只在下方标一次；模型 notes（R² 偏低、参数越界、协方差不可估）用红字写在残差条上方。`fit="linear"` 保持原样不开面板——线性 OLS 的传统画法就是单面板，而这条约束的动机（"看起来对"）针对的是有形状的模型。

三个踩过后写下来的判断：

1. **色散式换了参数化。** 原写法 `n∞ + S·λ²/(λ²−λ₀²)` 在远离极点时第二项趋于常数，而这个常数 `n∞` 已经能吸收——于是拟合出 R²=0.97、曲线贴合、三个参数全不对。改成 `n∞ + S·λ₀²/(λ²−λ₀²)`（振子项在长波端真的衰减）。极点必须落在数据之外，所以分短波/长波两个分支各拟合一次取残差小者，并把"另一分支未采用"写进 notes。
2. **没有数值简并门限。** 试过用参数相关系数与相对标准误设阈值，量下来分不开：幂律拟合的 |r|=0.9955 但参数回收误差 1e-4，色散拟合的 |r|=1.0000 且参数完全跑偏——两个数字之间没有可留余地的间隙。按"量不出来就删掉而不是调数字"处理，改成每个模型一句**结构性适用条件**（`caveat`），说明它的参数在什么情况下不再可辨识。色散的 caveat 正是"远离极点时只有 n∞ 与 S·λ₀² 的组合可辨识"，与实测一致。
3. **保留的唯一数值判据是量纲的，不是统计的。** 带横轴量纲的参数（τ、σ、γ、λ₀）若绝对值超过扫描范围 10 倍，直接说明"它在这批数据里只起常数作用，不是被测量出来的量"。这条分得开：过参数化时 τ=3.5e4 对扫描 8（差 4000 倍）触发，真双指数 τ₂=4.1 对扫描 8 不触发。

**参数置信区间仍然不给**（第一版决定不变）。协方差假设独立同分布高斯噪声，仪器读数通常不满足；`caveat` 与残差面板承担"这次能不能信"的判断，而不是给一个看起来严格实则无据的 ±。

**曲线族拒绝整体拟合**：按角度/温度分组时勾选模型直接报错，因为给十五条谱配一条线是把变化抹平成形状。

### N8 · 实物光路图 → 3D（第二阶段）
关键设计：让多模态模型输出**结构化场景 JSON**（元件类型、位置、朝向、波长），再由 three.js 确定性渲染。不要让模型直接生成 3D 渲染图——像素不可编辑、几何与比例常错。

```json
{"components":[{"type":"laser","pos":[0,0,0],"dir":[1,0,0]},
               {"type":"bs","pos":[120,0,0],"rot":45},
               {"type":"lens","pos":[240,0,0],"f":80}],
 "wavelength_nm":1550}
```

## 给合作者：新增一个图型的正确顺序

1. 定义图型 ID 与**完整的列编码契约**（需要哪些列、什么角色、缺了会怎样）
2. 在 `core.py` 的 `recommend()` 加适用条件与**等级**，并写清"为什么是高等级/为什么只是中"
3. 在 `render.py` 的 `_draw()` 加分支，显式消耗 `Recommendation.encodings`，不读全局状态
4. 用**真实失效边界**验证：空列、全缺失、单点、含负值、含 inf、超宽矩阵、重复坐标
5. 在 `catalog/styles.json` 补至少 3 个子类
6. 不要在渲染路径或界面里引用出处字段

**不要**把参考论文里的复杂功能直接写成已实现的产品功能。
